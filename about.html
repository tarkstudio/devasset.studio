◆ ABOUT DEVASSET STUDIO

We got tired of Android Studio just to make an icon.

DevAsset Studio is a small, honest tool — built by TarkStudio, an independent one-person software workshop — for the very specific, very repetitive job of turning one master image into a compliant asset bundle. No accounts. No servers. No uploads.

The friction that started this

If you've shipped more than a couple of apps, you already know the ritual. You finish the icon in your design tool, and then the real work begins: booting a multi-gigabyte Android Studio instance just to right-click New → Image Asset and watch it churn out res/mipmap-mdpi through mipmap-xxxhdpi — density buckets that Google's own tooling has been re-shuffling for a decade.

Then you switch to Xcode and it's a different fight entirely: hand-building an AppIcon.appiconset, getting the Contents.json scale factors exactly right, and praying you didn't fat-finger a size entry that Apple's validator will reject on upload. Add Samsung's One UI continuous-squircle icon shape on top of that, plus Amazon Fire OS's own asset quirks for sideloaded builds, and "just make an icon" turns into an afternoon.

That's the whole reason DevAsset Studio exists. The premise is simple, almost stubborn: one 1024×1024 master icon should be enough to generate a pixel-perfect, spec-compliant asset package for all four major ecosystems — Android, iOS, Samsung, Amazon — in seconds, not an afternoon.

How it actually works

DevAsset Studio runs 100% in your browser. There's no backend doing the heavy lifting — the "engine" is the HTML5 Canvas API resizing and rendering every density and idiom locally, and JSZip packaging the final output into a downloadable archive, all inside the tab you already have open.

// zero uploads

Your master icon, screenshots, and branding never leave your machine. There is no upload endpoint to send them to — this is a client-side app icon resizer, not a service that stores your artwork.

// zero tracking

No analytics pixels, no session recording, no behavioral tracking. We don't know what icon you made, and we've built it so we structurally can't know.

// zero database

There's no backend database because there's no backend. Once the page loads, everything from resizing to zipping happens in memory, on your device.

// offline-resilient

Once the page has loaded, it keeps working without an active connection — genuinely useful on a slow hotel Wi-Fi or a train, not just a marketing line.

Practically, that means DevAsset Studio functions as an Android mipmap generator, an iOS AppIcon bundle maker, and a Contents.json generator in one pass — including handling the Samsung One UI squircle icon mask and Amazon Fire OS's asset requirements — without a single byte of your proprietary artwork ever touching a server. For a solo developer or a small studio protecting unreleased branding, that's not a nice-to-have; it's the entire point of a zero-server-upload developer toolkit.

The workshop behind it — TarkStudio

DevAsset Studio isn't a company with a roadmap and a growth team. It's one tool out of TarkStudio, an indie software and tooling workshop built around a fairly unglamorous belief: the small, annoying, repetitive parts of shipping mobile software deserve just as much engineering care as the flashy parts.

TarkStudio builds focused developer utilities and client-side tools. It follows the same rule this asset generator follows: local-first performance where it's possible, no unnecessary accounts, no dark patterns, and no pretending a hobby-sized project is a "platform" with "enterprise-grade infrastructure." It's a workshop, not a SaaS company, and the tools are built the way their own maker actually wanted to use them.

If a tool doesn't save real time on a real, recurring workflow for a mobile creator, it doesn't get shipped. DevAsset Studio survived that filter because exporting icons is a task every app developer repeats, release after release, ecosystem after ecosystem — and it deserved a fifteen-second fix instead of a fifteen-minute one.

Found a bug, or an edge case we missed?

This is a small, actively maintained tool, not a support ticket queue. If a density bucket renders wrong, a squircle mask looks off, or a Contents.json entry doesn't validate — tell us directly.
